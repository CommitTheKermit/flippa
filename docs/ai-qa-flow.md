# AI와 함께 실행하는 Android QA

## 사용자 흐름

테스트 앱·기기를 선택한 뒤 시작 조건, 실행할 순서, 기대 결과를 입력한다. 앱 데이터는 자동 초기화하지 않는다. 로그인 등 시작 조건을 직접 준비한다. AI는 시작 조건을 확인하도록 지시받으며, 조건을 확인할 증거가 없으면 성공으로 간주하지 않는다.

1. UI 텍스트 전송에 동의하고 테스트를 지시한다.
2. 연속 조작을 선택하면 테스트 앱 안에서 탐색·로컬 입력을 실행한다. 선택을 해제하면 입력마다 확인한다.
3. 실행·승인 대기 동안 파란 테두리로 조작권을 표시하고 수동 입력을 막는다. 탭 대상은 주황색으로 잠시 표시한다. 화면 관찰·확대·축소·중지는 가능하다.
4. 전송·서버 저장·삭제·구매·권한 변경·불확실한 영향, 앱 이탈은 사람의 확인을 기다린다. 승인 직전 화면이 달라졌으면 실행하지 않는다.
5. 종료 후 기대 결과를 별도 검증한다. 통과·실패·확인 불가와 관측 ID를 기록한다. 마지막 허용 호출에서 조작했어도 검증 1회는 별도로 수행한다.
6. 같은 테스트를 반복하려면 시나리오로 저장한다. 저장 항목은 앱 패키지, 제목, 시작 조건, 실행 지시, 기대 결과다. 다시 실행할 때는 현재 화면에서 AI가 대상을 새로 찾으며, 좌표 녹화 재생 방식이 아니다. 전송 동의와 조작 권한은 저장하지 않고 실행 시 현재 선택을 적용한다.

AI의 영향 분류와 결과 판정은 모델 판단이다. 서버는 대상 앱, 입력 대상, 위험 문구, 키 종류, 최신 화면을 추가 검사한다. 버튼 문구 검사만으로 안전을 보장하지 않으며, 모델이 부작용을 잘못 분류할 가능성은 남는다. 운영 데이터 대신 준비한 테스트 앱·계정에 적용한다. 서버 상태 검증이나 앱 내부 상태·네트워크 수집·Mock 주입은 이 버전에 포함하지 않는다.

## 관측과 기록

- AI 실행 동안 앱 UID로 필터링한 `adb logcat`을 지속 수집한다. 앱 프로세스 재시작으로 PID가 바뀌어도 같은 UID의 로그를 수집한다. 동일 UID를 공유하는 패키지가 있으면 함께 포함될 수 있다.
- 기록은 실행 시작 이후의 수신 순서와 UTC 수신 시각을 가진다. ADB 연결 끊김·스트림 종료·UID 조회 실패는 누락으로 기록한다. 자동 재연결은 하지 않는다.
- 메모리에는 최근 5,000개 로그 청크, 파일에는 실행당 최대 10MiB를 보존한다. 상한을 넘으면 누락 표시를 남긴다.
- 각 AI 조작에 전후 UI 구조와 해당 구간 로그를 연결한다. 입력이 끝난 뒤 기본 0.4초 시점의 관측이며, 늦게 발생한 결과는 다음 관측이나 최종 관측으로 확인한다. 타임라인에서 단계를 선택해 내보내면 연결된 증거도 함께 선택되며 첨부 종류별 공유 선택은 그대로 적용한다.
- 이미지 저장·AI 전송은 별도 선택이다. 선택하지 않으면 AI는 UI 구조만 읽고 이미지를 캡처하거나 전송하지 않는다. 화면의 개인정보·비밀값은 자동 마스킹하지 않는다.
- 지속 로그의 로컬 수집과 외부 AI 전송 동의는 별개다. 로그 전송에 동의했을 때만 로그 조회 결과와 조작 구간 로그를 AI 판단에 사용한다.
- 수동 로그 조회는 기존 PID 최근 200줄 표본이다. 실시간 수동 터치마다 전후 화면을 자동 저장하지는 않는다.
- 통과·실패도 AI 판정이므로 `fact=false`로 남긴다. 관측 자료가 없거나 최종 화면 수집 실패, 중지, 모델 응답 실패는 확인 불가다. 서버의 실제 변경 결과처럼 관측으로 입증하지 못한 항목도 확인 불가로 판단하도록 지시한다.

## 같은 컴퓨터의 Codex에서 MCP 사용

실행 중인 플리파 작업실에 연결한다. 별도 기기를 띄우거나 별도 기록 폴더를 만들지 않는다. 로컬 단일 사용자 모드만 지원하며 원격 Mac-홈서버 연결 및 Unix 소켓 공동 사용자 모드는 지원하지 않는다.

1. 플리파를 실행하고 테스트 세션을 연다.
2. UI 텍스트·로그·이미지 전송 선택을 확인한 뒤 `로컬 MCP 연결 허용`을 누른다. 이미지·로그 선택은 각각 독립이다. 연결 허용 시 선택이 고정되며 변경하려면 해제 후 다시 허용한다.
3. 같은 컴퓨터의 터미널에서 아래 명령의 두 경로를 실제 설치 경로로 바꿔 등록한다. 플리파에서 사용하는 Python 경로를 사용한다.

```sh
codex mcp add plipa -- /absolute/path/to/python /absolute/path/to/plipa/plipa_mcp.py
```

Windows에서도 `python.exe`와 `plipa_mcp.py`의 절대 경로를 사용한다. 포트를 바꿨으면 명령 뒤에 `--url http://127.0.0.1:포트`를 붙인다. 서버에 `PLIPA_ORIGIN`을 설정했다면 어댑터에도 같은 환경변수 또는 `--origin` 인수를 지정한다. 접속 주소는 계속 loopback이며 인증값을 명령 인수에 넣지 않는다.

노출 도구:

| 도구 | 역할 |
| --- | --- |
| `plipa_status` | 현재 세션, 실행·승인·결과 조회, 연결 갱신 |
| `plipa_begin` | 목표·기대 결과·시작 조건으로 실행 시작 |
| `plipa_observe` | 최신 UI 구조와 동의한 이미지 조회 |
| `plipa_logs` | 동의한 앱 로그 조회 |
| `plipa_environment` | 앱·기기 버전 조회 |
| `plipa_act` | 최신 관측 ID에 연결된 조작 요청 |
| `plipa_finish` | 플리파의 Codex로 독립 검증 후 조작권 반환 |
| `plipa_cancel` | 실행 중지 |

`begin`이 돌려준 실행 ID와 `observe`의 관측 ID를 사용한다. 위험 조작은 웹에서 사람이 승인한다. MCP에 승인 도구는 없다. 승인 후에는 `status`를 확인하고 다시 `observe`한다. `finish`의 검증에는 플리파 서버의 Codex 로그인이 필요하다.

연결은 120초 미사용 시 종료하고 확인 불가로 기록한다. 장시간 추론 중에는 `status`로 갱신한다. 정상적인 stdio 종료에서는 취소를 요청한다. 서버 재시작·새 세션·기록 전환 후에는 MCP 연결 허용을 다시 선택해야 한다. 수동 조작 차단과 승인 경로는 내장 AI와 동일하다.

MCP 어댑터는 JSON-RPC 2.0, MCP 2025-06-18의 stdio 전송과 tools/list·tools/call을 사용한다. 표준 출력에는 프로토콜 메시지만 기록한다.

근거: [MCP stdio 규격](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports), [MCP tools 규격](https://modelcontextprotocol.io/specification/2025-06-18/server/tools), 설치된 `codex exec --help`의 `--image`, `--output-schema` 옵션.

## 검증

```sh
.venv/bin/python -m unittest -q
node --check dist/app.js
node test_stream.mjs
```

2026-10-11: Python 테스트 42개, JavaScript 구문·스트림 프레임 검사를 통과했다. 브라우저에서 저장·재실행·승인 취소·입력 잠금 흐름을 검증했다. MCP 프로세스를 실제 stdio로 실행해 HTTP 작업실에 연결하고 초기화·도구 조회·이미지 관측·조작·최종 판정을 확인했다. Android 응답과 브라우저 검증의 모델 응답은 테스트 대역이다. 합성 이미지·UI 텍스트로 실제 Codex를 호출해 조작 스키마 응답과 근거 ID가 있는 최종 검증 응답도 확인했다. 연결된 실제 Android 기기가 없어 기기 연동은 미검증이다. 서버 배포와 전역 Codex MCP 등록은 수행하지 않았다.
